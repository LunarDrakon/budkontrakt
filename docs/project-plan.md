# Опис проєкту

## Тема

Вебзастосунок для сайту ремонтно-будівельної компанії — показує послуги компанії та дозволяє клієнтам залишати заявки на ремонт чи будівництво.

## Проблема

Клієнту не завжди зрозуміло, які послуги надає компанія, скільки це коштує і як зробити замовлення. Компанії теж незручно, коли заявки приходять через різні канали (дзвінки, месенджери) і губляться.

## Сутності

- **Послуга** — id, назва, категорія (ремонт квартир, будівництво будинків, оздоблювальні роботи, електрика, сантехніка), опис, орієнтовна ціна, доступність.
- **Заявка** — id, посилання на послугу, ім'я клієнта, номер телефону, опис робіт, площа об'єкта та інформація про необхідність виїзду майстра для замірів.

## Групи користувачів і сценарії

| Група | Потреба | Основний сценарій |
|---|---|---|
| Відвідувач | Дізнатись, що пропонує компанія | Переглянути список послуг |
| Клієнт | Замовити ремонт/будівництво | Обрати послугу, залишити заявку |
| Менеджер | Опрацювати звернення | Переглянути заявки, змінити їхні дані |

## Сценарій: перегляд каталогу послуг

Користувач: відвідувач

Передумова: відкрито застосунок.

1. Переходить до розділу з послугами.
2. Бачить назву, категорію і ціну кожної послуги.
3. Знаходить потрібну послугу.

Результат: розуміє, яку послугу хоче замовити.

Альтернатива: список послуг порожній — виводиться повідомлення про це.

## План сторінок

| Сторінка | Призначення | Шлях |
|---|---|---|
| Головна | Про компанію, переваги | `/` |
| Послуги | Список послуг | `/services` |
| Послуга | Деталі однієї послуги | `/services/:serviceId` |
| Заявки | Перегляд, пошук, фільтрація та сортування заявок | `/requests` |
| Створення заявки | Створення нової заявки | `/requests/new` |
| Деталі заявки | Перегляд інформації про конкретну заявку | `/requests/:requestId` |
| Редагування заявки | Редагування існуючої заявки | `/requests/:requestId/edit` |

## Навігація

Для переходів між сторінками використовується React Router.

Основні маршрути вебзастосунку:

- `/` — головна сторінка;
- `/services` — список послуг;
- `/services/:serviceId` — детальна інформація про послугу;
- `/requests` — список заявок;
- `/requests/new` — створення нової заявки;
- `/requests/:requestId` — перегляд деталей заявки;
- `/requests/:requestId/edit` — редагування заявки;
- `*` — сторінка для невідомого маршруту.

Для фільтрації послуг використовується параметр пошуку в URL, наприклад `/services?search=ремонт`.

У розділі заявок також використовуються параметри URL для пошуку, фільтрації та сортування. Наприклад: `/requests?q=Іван&survey=yes&sort=area-asc`.

Розділ заявок має вкладену навігацію. Спільна частина сторінок реалізована через `AppLayout` та `Outlet`.

## Модель заявки (ЛР 3.1)

Головна сутність для CRUD-сценарію — заявка на послугу компанії.

| Поле | Правило |
|---|---|
| id | Стабільний ідентифікатор, створюється операцією додавання, у формі не редагується |
| serviceId | Посилання на наявну послугу з каталогу |
| customerName | Обов'язковий текст, від 2 до 50 символів після видалення крайніх пробілів |
| phone | Обов'язковий, формат +380XXXXXXXXX (пробіли, дужки й дефіси при перевірці ігноруються) |
| description | Обов'язковий текст, від 10 до 500 символів після видалення крайніх пробілів |
| area | Обов'язкове ціле число від 1 до 500 (орієнтовна площа об'єкта, м²) |
| needsSurvey | Логічне значення; для площі понад 100 м² виїзд майстра для замірів обов'язковий |

Правила перевірки зібрані в одній функції та використовуються під час перевірки форми й операцій із колекцією заявок. Помилки показуються біля відповідних полів українською мовою.

## Операції із заявками (ЛР 3.1)

Для роботи із заявками реалізовано основні CRUD-операції:

- **Create** — створення нової заявки;
- **Read** — перегляд списку та детальної інформації про заявку;
- **Update** — редагування даних існуючої заявки;
- **Delete** — видалення заявки після підтвердження користувачем.

Для спільної роботи зі списком заявок використовується `RequestsContext` та хук `useRequests`. Це дозволяє отримувати колекцію заявок і виконувати операції з нею на різних сторінках застосунку.

Форма створення та редагування заявки використовує контрольовані поля. Якщо під час перевірки виявлено помилки, вони відображаються біля відповідних полів, а введені користувачем значення зберігаються. Перехід на іншу сторінку відбувається після успішного виконання операції.

## Пошук, фільтрація та сортування заявок (ЛР 3.1)

На сторінці списку заявок реалізовано:

- пошук за іменем клієнта та описом робіт;
- фільтрацію за необхідністю виїзду майстра для замірів;
- сортування за іменем клієнта та площею об'єкта;
- збереження параметрів пошуку, фільтрації та сортування в URL.

Якщо колекція заявок порожня, відображається відповідне повідомлення. Якщо заявки є, але вони не відповідають заданим умовам пошуку чи фільтрації, користувач бачить окреме повідомлення про відсутність результатів.

## Зберігання даних

Дані заявок зберігаються лише в пам'яті запущеного застосунку: вони переживають переходи між сторінками, але після перезавантаження документа відновлюються початкові записи з `src/data/requests.js`.

Заявка означає запит на розрахунок і виконання робіт, а не підтверджене замовлення.
