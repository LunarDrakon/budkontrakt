# Компонентна архітектура

## 1. Призначення застосунку

Застосунок розробляється для веб-сайту ремонтно-будівельної компанії.

Основне призначення сайту — представити послуги компанії та надати користувачу можливість переглядати їх, знаходити потрібну послугу та залишати заявку.

## 2. Основні частини інтерфейсу

Основними частинами інтерфейсу є:

- спільна шапка сайту;
- основна навігація;
- головна сторінка;
- список послуг;
- картки окремих послуг;
- сторінка деталей послуги;
- розділ заявок;
- сторінка створення заявки;
- сторінка редагування заявки.

## 3. Компонентна ієрархія

Основна структура компонентів має такий вигляд:

App
└── AppLayout
    ├── SiteHeader
    ├── MainNav
    └── Outlet
        ├── HomePage
        ├── ServicesPage
        │   └── ServiceList
        │       └── ServiceCard
        ├── ServiceDetailsPage
        └── RequestsLayout
            ├── навігація розділу заявок
            └── Outlet
                ├── RequestsPage
                ├── RequestCreatePage
                └── RequestEditPage

## 4. Відповідальність компонентів

### App

Кореневий компонент React-застосунку. Містить опис маршрутів вебзастосунку та визначає, який компонент потрібно відображати для кожної адреси.

### AppLayout

Спільна маршрутна оболонка застосунку. Містить `SiteHeader`, `MainNav` та `Outlet`.

Через `Outlet` у цьому компоненті відображається вміст поточного маршруту.

Також у `AppLayout` розміщений `SelectedServiceProvider`, тому вибрана послуга доступна для потрібних дочірніх компонентів.

### SiteHeader

Відповідає за відображення назви ремонтно-будівельної компанії та короткого опису її діяльності.

### MainNav

Містить основну навігацію сайту. Для переходів між маршрутами використовується `NavLink`.

Основні переходи:

- головна сторінка;
- послуги;
- заявки.

### HomePage

Головна сторінка веб-сайту. Містить інформацію про компанію, пошук послуг, список послуг та форму заявки.

### ServicesPage

Сторінка зі списком усіх послуг компанії. На цій сторінці реалізовано пошук послуг із використанням параметра `search` в URL.

### ServiceList

Відповідає за відображення списку послуг. Отримує масив послуг через `props` та передає окремі записи до `ServiceCard`.

### ServiceCard

Відображає інформацію про одну послугу. У картці показуються назва, категорія, опис, ціна та доступність послуги.

Назва послуги містить `Link`, який відкриває сторінку деталей за адресою `/services/:serviceId`.

### ServiceDetailsPage

Відображає детальну інформацію про вибрану послугу.

Для отримання `serviceId` з адреси використовується `useParams`. Якщо послугу з таким ідентифікатором не знайдено, відображається повідомлення про її відсутність.

### RequestsLayout

Маршрутна оболонка розділу заявок. Містить локальну навігацію за допомогою `NavLink` та `Outlet` для відображення дочірніх маршрутів.

Через нього відкриваються сторінки списку заявок та створення нової заявки.

### RequestsPage

Відображає сторінку зі списком заявок.

### RequestCreatePage

Відповідає за сторінку створення нової заявки. Для кнопки скасування використовується `useNavigate`, який повертає користувача до `/requests`.

### RequestEditPage

Відповідає за сторінку редагування заявки. Ідентифікатор заявки отримується з URL за допомогою `useParams`.

### NotFoundPage

Відображається для невідомих маршрутів. Містить повідомлення про те, що сторінку не знайдено, та посилання для повернення на головну сторінку.

## 5. Дані

Дані про послуги зберігаються окремо у файлі:

src/data/services.js

Це дозволяє не змішувати дані предметної області з кодом компонентів.

## 6. Маршрутизація

Для маршрутизації використовується React Router.

Основні маршрути:

- `/` — головна сторінка;
- `/services` — список послуг;
- `/services/:serviceId` — деталі окремої послуги;
- `/requests` — список заявок;
- `/requests/new` — створення нової заявки;
- `/requests/:requestId/edit` — редагування заявки;
- `*` — невідомий маршрут.

Для розділу заявок використовується вкладена маршрутизація. `RequestsLayout` містить `Outlet`, через який відображаються дочірні сторінки.

## 7. Навігація

Для переходів між сторінками використовуються засоби React Router:

- `Link` — для переходу до деталей послуги;
- `NavLink` — для основної та вкладеної навігації;
- `useParams` — для отримання параметрів маршруту;
- `useSearchParams` — для роботи з параметром пошуку в URL;
- `useNavigate` — для програмної навігації.

Пошук послуг використовує параметр URL, наприклад:

/services?search=ремонт

Це дозволяє зберігати поточний параметр пошуку в адресі сторінки.

## 8. Керування станом

У застосунку використовується декілька способів керування даними та станом.

### Локальний стан

Для даних, які використовуються тільки в межах поточного сценарію, використовується `useState`.

До локального стану належать:

- `request.name` — ім'я користувача;
- `request.phone` — номер телефону.

Пошуковий текст на сторінці `ServicesPage` окремо в `useState` не зберігається. Він береться з параметра `search` в URL через `useSearchParams`.

### Власний хук

Для логіки фільтрації на головній сторінці створено власний хук `useServiceFilter`.

Він працює з текстом пошуку та формує список `visibleServices` на основі початкового масиву `services`.

### Context API

Для спільного вибору послуги створено `SelectedServiceContext`.

Провайдер `SelectedServiceProvider` розміщений у `AppLayout`, тому необхідні дочірні компоненти можуть отримувати доступ до вибраної послуги.

Споживачами контексту є:

- `ServiceCard` — змінює вибрану послугу;
- `RequestSummary` — відображає вибрану послугу.

Такий підхід дозволяє не передавати вибрану послугу через декілька рівнів `props`.

### Ефект

У `HomePage` використовується `useEffect` для зміни назви вкладки браузера залежно від вибраної послуги.

При виборі послуги назва вкладки змінюється, а після очищення вибраної послуги повертається стандартна назва.

## 9. Використання React Bootstrap

Для оформлення окремих елементів інтерфейсу використовується бібліотека React Bootstrap.

Зокрема, компонент `Card` використовується для відображення окремої послуги в `ServiceCard`.

React Bootstrap використовується разом із власними CSS-стилями проєкту.

## 10. Повторне використання компонентів

Компонент `Section` використовується для різних секцій сторінок.

Компонент `ServiceList` використовується для відображення списку послуг, а `ServiceCard` — для відображення окремої послуги.

`AppLayout` та `RequestsLayout` використовуються як спільні оболонки для відповідних маршрутів.

Такий поділ дозволяє повторно використовувати компоненти та спрощує подальше розширення вебзастосунку.
